**Headline:** The engineering and the detail pages (match/team) are strong; the risk is **scale applied to thin/unlocalized data**. Three dominant themes: (1) **thin-content + soft-404 SEO exposure** across 31.7k player + 12.4k match + 1.5k team URLs with only a single `unknown-%` gate; (2) **the data layer isn't localized** — team/country/competition/round/stat names render English/Latin on FR & AR, and Arabic entity pages contain no Arabic names; (3) **analytics are blind** for non-consenting visitors (a consequence of the opt-in gate), so none of this is measurable. Plus a **red test suite** and a recurring **undefined-design-token** class of bug.

## 3. Conflicts resolved (page goal wins)

- **SEO "more content" vs conversion "less clutter" on the WC2026 hub:** SEO wants rich prose; conversion flags 18k px burying the table. **Resolution (per `pages.md` goal = "state of the competition, drill into matches"):** deciding info (table/fixtures) first with a sticky jump bar; keep editorial but **below** the data (and move tickets/visa/travel out per the `/review` finding). Both satisfied.
- **SEO thin-page "improve or noindex" vs keeping 45k URLs for coverage:** page goal for player/team = "enough info to decide." Empty pages don't meet it → **noindex empties, improve the ~200 players with real demand** (B2/B3). Not a real conflict once the goal is applied.
- **Consistency "no undefined color tokens" vs code "more undefined tokens found":** code-reviewer's grep is authoritative — there **are** more (`text-text-quaternary` etc.). B8 stands.
